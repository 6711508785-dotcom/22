# 5W1H Detective Adventure — Multiplayer 50 คน

ชุดนี้ต่อยอดจากไฟล์เกมเดิมที่ผู้ใช้ส่งมา โดยคง `game.js`, `index.html`, `style.css` และเพิ่มระบบห้องออนไลน์ด้วย Colyseus

## สิ่งที่เพิ่มในชุดนี้
- ครูสร้างห้องด้วย Teacher PIN
- นักเรียนเข้าด้วยรหัสห้อง
- จำกัดผู้เล่นรวมครูไม่เกิน 50 คนต่อห้อง
- รายชื่อผู้เล่นและสถานะห้อง
- ซิงก์ตำแหน่ง/การหมุน/รูปลักษณ์ตัวละครผ่าน WebSocket
- แผงควบคุมครู: เริ่ม, หยุดชั่วคราว, เล่นต่อ, จบ และเลือกภารกิจ
- ผู้เล่นที่เข้าห้องเดียวกันจะเห็นตัวละคร 3D ของกันและกัน

## โครงสร้างไฟล์
- `index.html`, `game.js`, `style.css` — เกมเดิมที่ปรับการเชื่อมต่อ
- `multiplayer-client.js` — หน้าสร้าง/เข้าห้องและ client ของ Colyseus
- `server/index.js` — เซิร์ฟเวอร์ห้อง Multiplayer
- `package.json` — dependencies และคำสั่งรัน

## 1) ตั้งค่าเซิร์ฟเวอร์ในเครื่องเพื่อทดสอบ

ต้องติดตั้ง Node.js 20 ขึ้นไป

Windows PowerShell:
```powershell
npm install
$env:TEACHER_PIN="ใส่รหัสครูที่คาดเดายาก"
npm start
```

เซิร์ฟเวอร์จะเปิดที่ `http://localhost:2567` และ WebSocket ที่ `ws://localhost:2567`

เปิดเกมจาก local web server (อย่าเปิด `index.html` ด้วย file://) และ client จะใช้ `ws://localhost:2567` อัตโนมัติเมื่อ hostname เป็น localhost

## 2) นำขึ้นออนไลน์

GitHub Pages ใช้โฮสต์หน้าเกมได้เท่านั้น ส่วน `server/` ต้องนำไป deploy บนบริการที่รองรับ Node.js และ WebSocket เช่น Render, Railway หรือ Fly.io

ตั้งค่า environment variable บนบริการโฮสต์:
- `TEACHER_PIN` = รหัสลับของครู
- `PORT` = ถ้าผู้ให้บริการกำหนด (โค้ดอ่านค่า PORT ให้อัตโนมัติ)

หลัง deploy ให้แก้ `multiplayer-client.js` บรรทัด `SERVER_URL` จาก:
```js
: "wss://YOUR-MULTIPLAYER-SERVER.example.com");
```
เป็น URL WebSocket จริงของเซิร์ฟเวอร์ เช่น:
```js
: "wss://ชื่อบริการของคุณ.example.com");
```
ต้องเป็น `wss://` เมื่อหน้าเกมทำงานผ่าน HTTPS

จากนั้น commit และ push ไฟล์หน้าเว็บไป GitHub Pages อีกครั้ง และ deploy โฟลเดอร์โปรเจกต์นี้ไปยัง Node hosting

## 3) วิธีใช้ในห้องเรียน
1. ครูเปิดหน้าเกม เลือก “ครูสร้างห้อง”
2. กรอก Teacher PIN แล้วกดสร้างห้อง
3. แจ้งรหัสห้องให้นักเรียน
4. นักเรียนเปิดหน้าเกม เลือก “นักเรียนเข้าห้อง” กรอกชื่อ เลขที่ และรหัส
5. ครูและนักเรียนกด “เข้าสู่เกม 3D”
6. ครูใช้แผงควบคุมด้านขวาเพื่อเริ่ม/หยุด/จบเกม

## ข้อจำกัดและสิ่งที่ต้องทดสอบก่อนใช้จริง
- ชุดนี้เป็นโครงสร้าง Multiplayer รุ่นเริ่มต้น ต้องตั้งค่า URL เซิร์ฟเวอร์จริงและทดสอบบนเครือข่ายจริงก่อนใช้กับนักเรียน
- 50 คนเป็นเพดานต่อห้อง ไม่ใช่การรับประกันประสิทธิภาพบนทุกแพ็กเกจโฮสต์ ต้องทดสอบพร้อมกัน 5, 20, 40 และ 50 เครื่อง
- ตำแหน่งตัวละครส่งประมาณ 10 ครั้งต่อวินาทีต่อผู้เล่น และเซิร์ฟเวอร์เป็นผู้กระจายสถานะให้คนในห้อง
- การซิงก์ตำแหน่งและรูปลักษณ์ทำงานในชุดนี้ ส่วนคะแนนออนไลน์ยังไม่เปิดให้ client ส่งคะแนนโดยตรง เพื่อป้องกันการปลอมคะแนน ต้องย้ายการตรวจคำตอบและคำนวณคะแนนมาไว้ฝั่ง server ก่อนเปิดใช้ตารางคะแนนรวมอย่างเป็นทางการ
- ระบบ reconnect, persistence ของคะแนน, การจัดการผู้เล่นหลุด, การยืนยันตัวตนครูที่แข็งแรงขึ้น และการป้องกันการส่งข้อมูลถี่ผิดปกติ ควรเพิ่มและทดสอบในรอบถัดไป
- ผู้เล่น 50 คนอาจใช้ทรัพยากรเครื่องนักเรียนมาก โดยเฉพาะมือถือรุ่นเก่า; ควรทดสอบกราฟิกและประสิทธิภาพจริง
